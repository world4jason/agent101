What is an Agent?

Agent = 有目標、能行動、會看結果、再繼續

GOAL我要達成什麼？

→

LLM 產生下一步判斷；Agent/App 把目標、工具、環境與多步驟 loop 組起來。

How do I start?

不用先找「Create Agent」；先從工作入口開始

CODING AGENT Claude Code

MULTI-STEP WORK ChatGPT Work

把多步驟工作交出去，跨檔案、工具或網站完成，而不是只問一個單輪問題。

不要把「新 chat」硬等同「新 Agent」。先看這個產品怎麼組 目標、context、tools、environment、permissions。

不是「LLM 自己永久記住專案」。Runtime 會把相關資訊帶到下一次 call；可以是原文、摘要、retrieval 或 tool results，不代表每輪逐字重送全部歷史。

Agent vs Environment

Agent 決定下一步；Environment 才是實際執行的地方

LOCAL
在你的電腦 / worktree 執行
讀寫本機 repo
跑 local test / build
受本機憑證與權限限制
CLOUD
在 sandbox / VM / browser environment 執行
隔離的工作環境
可跨網站 / 雲端工具
受 cloud sandbox 與授權限制

Tool access ≠ Permission。 看得到某個工具，不代表這次就被允許直接修改、發送或部署。

Optional · Capability Map

缺什麼能力，再加什麼；不要先把工具裝滿

這類事情每次都要照同一套方法？→ Skill
要查公開網路的最新資訊？→ Web Search
要找公司 / 專案私有知識？→ RAG
要讓 Agent 使用外部工具 / 資料介面？→ MCP
要把 Gmail / Drive / GitHub 等帳號能力接進產品？→ Connector / Plugin
要隔離一個專責 worker / context？→ Subagent
大型交付需要更完整的 spec / planning discipline？→ SDD / BMAD

這不是 glossary。每一個名詞都只在你先有一個具體 capability gap時才有意義。

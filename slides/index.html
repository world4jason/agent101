Human Acceptance

非技術的人不用看懂 code；你只要把驗收拆成四個問題。

1有東西可驗嗎？PR、Preview、Evidence 是否齊全。
2基本檢查過了嗎？Build、Test、安全檢查有沒有明顯紅燈。
3行為符合 AC 嗎？自己操作最重要的 scenario。
4真的解決問題嗎？最後才做產品判斷。
練習

這種「完成」，你會 approve 嗎？

AC 寫著：「未登入按收藏要要求登入。」

Agent 只回：「已完成。」沒有 Preview、沒有截圖、沒有測試結果。

ApproveRequest Changes

理由：沒有可獨立檢查的成果，就還沒到 Done。

Context

不要追求「永遠不忘記的 Agent」；要讓工作離開聊天後仍然存在。

聊天裡

當前討論、暫時假設、執行細節。

外部狀態

Spec、Issue、Commit、PR、Evidence。

Context 可以重開；專案狀態不能消失。

Method Map

BDD、TDD、SDD、BMAD 不是四個競品，而是處理不同層次的問題。

BDD把期望行為用 examples 對齊。 TDD建立 Red → Green → Refactor 的 feedback loop。 SDD工作夠大時，用 spec 驅動 plan / tasks / implementation。 BMAD工作更複雜時，把 clarify / plan / build / verify 制度化。
最後只帶走一句
你的工作不是「下 prompt」。
是設計一條可以被驗證的工作流程。

先把問題說清楚，先定義完成，再讓 Agent 做；最後用證據驗收。

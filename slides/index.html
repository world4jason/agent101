Agent 101 · Human + Agent 協作入門

管 AI 專案，
本質是管工作

不先學提示詞技巧，也不先背工具。先把工作變成 可委派、可追蹤、可驗收、可交付。

以前你把工作交給同事；現在也可以交給 Agent。工作管理沒有重來，協作介面變得更明確。
From coworker → Agent

你已經會把工作交給人；
Agent 只是把合作條件變得更明確

你交代同事你交代 Agent
說清楚要完成什麼→目標 / 工作（Goal / Task）
交代背景、現況與規則→工作脈絡 + 指令（Context + Instructions）
給文件、系統與可做的權限→檔案 + 工具 + 權限（Files / Tools / Permissions）
同事做事、回報結果→行動 → 觀察（Act → Observe）
你判斷要不要繼續 / 驗收→繼續 / Human 驗收（Continue / Review）

Agent = 能為目標採取行動、觀察結果，再繼續的 AI 工作者。 類比只幫你理解委派；最後怎麼定義問題、做取捨、決定是否驗收，仍由 Human 負責。

Agent 裡面有哪些東西？

LLM 只是其中一層；
Agent/App 還要管理工作狀態、工具與規則

AGENT / APP / RUNTIME
指令（Instructions）系統 / 專案 / 任務規則
工作對話 / Session這段工作的對話 / 執行邊界；不是 Agent 身分本身
工具 + 執行環境 + 權限能做什麼、在哪裡做、允許做到哪
正式專案狀態 + 可選記憶project docs / issues / code 等正式狀態 + 可選的 product / harness memory
↓ 組成這一步 ↓
目前工作脈絡（Current Context） 目前 task + relevant conversation + files / knowledge + tool results → LLM / Model

這些能力多半是 Agent/App/runtime 提供給模型。Context 是「這一步模型能用什麼」；Durable project state 是正式依據；product / harness Memory 只是可選的長期 context 來源。

Agent loop 怎麼運作？

LLM 做這一步推理；
Agent/App 把下一輪需要的東西組回來

目前輸入（Current Input）task + instructions + relevant context
→
LLM判斷下一步
→
工具 / 行動（Tool / Action）呼叫工具或執行動作
→
觀察結果（Observation）工具 / 環境回傳結果
↺
指令（Instructions）Conversation / SessionFiles / KnowledgeDurable state / optional MemoryTool results

模型只對這一步拿到的 context做推理。Agent/App 可能挑選、摘要、取回或引用相關狀態；不代表每輪逐字重送全部歷史。

這些概念在產品裡長什麼樣？

先懂 Agent，再看產品：
Codex / ChatGPT 只是把同一套概念落到不同介面

概念CodexChatGPT
工作對話 / Sessionchat / window / threadChat / Work task
專案邊界（Project boundary）repo / projectWork workspace / files / connected sources
指令（Instructions）AGENTS.md + task instructionsworkspace / task instructions + 你的指令
目前工作脈絡（Current Context）conversation + relevant files + tool resultsChat / Work + files + tool results
工具（Tools）terminal / files / code / allowed integrationsbuilt-in tools + Plugins / Connectors
執行環境 / 權限local / cloud coding environment + allowed actionsWork cloud environment + action approvals
正式專案狀態 + 可選記憶repo docs / issues / files；harness 可另外帶 memoryfiles / docs / connected sources + optional product Memory
Codex開 project / repo → 開工作對話 → 給 task
ChatGPT Work開 Work → 給 task + 需要的 files / tools
這是概念對照，不是一對一產品標準。Claude Code 也可用同樣方式理解：project + CLAUDE.md / rules + tools + work conversation。

新對話 / 新視窗 ≠ 新 Agent。 AGENTS.md 是專案指令（project instructions）的一種實作；MEMORY.md 不是通用標準。Product Memory 可以提供 context，但不是專案的正式依據。Tool access 也不等於 permission。

先分工作層級，
再談它現在做到哪

Specify · Ticket + Acceptance Criteria

工作票要讓別人不用猜；
AC 要能明確通過 / 不通過

RUNNING EXAMPLE · #42 手機版報名 CTA
#42手機版固定顯示「立即報名」CTA
目標（Goal）

降低使用者在手機上找不到報名入口的阻力。

範圍（Scope）

在手機版加入固定底部「立即報名」CTA。

明確不做（Non-goals）

不重做整份報名表；不改活動頁資訊架構。

負責人 / 優先順序 / 上層工作

Agent A · P1 · 改善報名入口

驗收條件（AC）

① 390px 手機寬度完整顯示「立即報名」
② 捲動時 CTA 固定在底部
③ CTA 不遮住主要內容，且沒有水平捲軸

驗收證據（Evidence）

可操作預覽 + 桌機 / 手機截圖 + 自動檢查

Review · Acceptance

Agent 說「完成」
只代表可以開始審查

RUNNING EXAMPLE · PR #71
PR #71 · 手機版報名 CTA
驗收證據可操作預覽 + 截圖 + 自動檢查 ✅
AC 1390px 完整顯示「立即報名」 ✅
AC 2捲動時 CTA 固定底部 ✅
AC 3CTA 遮住主要內容 ❌
已知限制尚未簡化報名步驟；符合明確不做的範圍
你會通過（Approve）嗎？建置 / 測試都通過，但 AC 3 失敗。
通過（Approve）
退回修改（Request Changes） ✓一條已約定的 AC 失敗，就還不能過。

審查要看：驗收證據 + AC + 範圍 + 已知限制 + Human 決定。Agent 自己說完成、自動檢查通過，都不等於自動驗收。

先定 Human 的責任；
再談 Agent 可以扮演什麼角色

Agent 可以做某個角色的工作；Human 的最終責任不會因為用了 Agent 就消失。

選修 · Agent 架構

後面的能力都只是插回五個位置；
Agent loop 沒有換一套

01指令（Instructions）專案規則 / Skills
例：AGENTS.md · CLAUDE.md
02工作脈絡（Context）目前工作 / 檔案 / 查回來的專案知識
例：可選的產品記憶（Memory）
03工具（Tools）可以呼叫的外部能力
例：內建工具 · Web Search · MCP · Connectors
04執行環境（Environment）動作在哪裡執行
例：本機 · 雲端隔離環境
05權限（Permissions）哪些讀取 / 修改 / 執行需要 Human 確認

回想 Slide 4：輸入 → LLM → 動作 → 觀察結果。產品記憶可以提供工作脈絡；它不是專案的正式依據。

選修 · 能力地圖

不要先把工具裝滿；
先問你缺什麼能力

每次都要照同一套方法？→ Skill｜可重用工作方法
要找公司 / 專案私有知識？→ RAG｜先檢索，再回答
要接外部工具 / 資料介面？→ MCP｜外部能力連接協定
要把 SaaS / 帳號能力接進產品？→ Connector / Plugin｜產品整合
要隔離專責工作者 / 工作脈絡？→ Subagent｜獨立工作者 / 工作脈絡
大型交付需要更完整的規格 / 規劃方法？→ SDD / BMAD｜大型交付方法

這不是名詞表。先遇到能力缺口，再加工具 / 方法。

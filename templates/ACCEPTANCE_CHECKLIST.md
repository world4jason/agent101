# Non-technical Acceptance Checklist

## 1. Requirement

- [ ] 我知道這次要解決什麼問題。
- [ ] 我知道這次 Scope。
- [ ] 我知道這次 Non-goals。

## 2. Delivery

- [ ] 有對應 Issue / Ticket。
- [ ] 有 PR 或明確交付紀錄。
- [ ] 有 Preview / 可操作成果。
- [ ] 有人話摘要，不需要先讀 code 才知道改什麼。

## 3. Acceptance Criteria

- [ ] 每條 AC 都能 Pass / Fail。
- [ ] 每條 AC 都有對應證據。
- [ ] 我可以自己重現核心 Scenario。
- [ ] 重要 edge case 已被列出或明確排除。

## 4. Quality Evidence

- [ ] Automated checks 沒有 blocker。
- [ ] UI 變更有 Before / After。
- [ ] 需要支援的 Desktop / Mobile 狀態已驗。
- [ ] 已知限制有被揭露。

## 5. Scope Control

- [ ] Agent 沒有未經同意擴大需求。
- [ ] 額外發現的問題有另外開 Ticket，而不是偷偷一起改。

## Decision

- [ ] Approve
- [ ] Request Changes
